## 3. Deliverable and target definitions

For a selected passage, return a bounded candidate account with evidence anchors:

1. **Contribution/process:** candidate operations and their ordering/dependencies, actor roles, possible tools and retained/changed/rejected material where the observation supports them.
2. **Local purpose:** compatible candidate aims and their support, tied to specific operations and passage evidence.
3. **Governing purpose:** include the best-supported broader purpose and its alternatives even if it does not improve detection. Mark speculative interpretation as such; no benchmark score for private intent is implied. Distinguish purpose adopted for this work from enduring preference and external pressure.
4. **Maker compatibility:** evidence needed to compare this episode with a continuing maker model; retain provenance and context fields, but do not score enduring values without ground truth.

Keep recorded, inferred, unavailable and contradicted facts distinguishable. A probabilistic claim that an operation occurred is different from a judgment that the maker understood or endorsed it. Acceptance without editing is not proof of inattention or endorsement. A retained model phrase is not a measurement of total human contribution. Do not create an authorship-share scalar from event counts.

The existing `ReadingProfile.ClaimBoundary.provenance` permits only `known_from_records` or `not_inferred`. Preserve that historical guard. Add the separately evaluated detector output through a versioned outer schema rather than relabel inferred process support as known provenance or silently widening the old field.

Several goals can coexist. Use calibrated nonexclusive marginals or a distribution over coherent **goal sets**, not a forced sum-to-one cloud over nonexclusive goals. Mutually exclusive process alternatives can use a normalized distribution. Keep unknown/outside-candidate support explicit. In real text this is a learned or declared reject estimate, not an exact probability over every imaginable omitted history. When panels are linked, retain joint samples or compatibility links: separately likely marginals must not be presented as a jointly likely account. A marginal's uncertainty, an outcome distribution's spread and a confidence interval are different quantities.

The proposed word cloud is an output consumer. Its relative sizes may mean calibrated support only after that readout validates; before then label them as candidate support, with honest uncertainty. A narrow but wrong distribution is failure, not progress.

### B. Retrospective process and local-goal reconstruction

**Question:** Does a joint account of possible goals and executable steps recover recorded contribution better than direct reading, retrieval and exact alignment on the same evidence?

Use Stage 11's actual retrospective episode boundary and source reconstructor, not LP16's prospective target. Expand source coverage after auditing prior exposure. A case can be new to this campaign without being untouched by earlier development or pretraining. Keep that distinction visible.

The minimum matched comparison is:

| Method | Function | Why required |
|---|---|---|
| Smoothed source/class prior | Uses training frequencies, respecting writer/source balance | Prevents base-rate gains being called reconstruction |
| Exact extraction/alignment and cheap diff | Reads explicit records or aligns actual changes under the same interface | Prevents an LLM getting credit for a simpler observable operation |
| Retrieval/example memory | Retrieves matched training cases without the proposed joint structure | Tests whether a mechanism adds more than familiar examples |
| Strong direct reader | Predicts the same targets using the same available evidence | Main inference rival |
| Proposal plus externally scored joint model | Proposes candidate goals/processes, calculates/checks their consequences, then combines evidence | Tests the proposed mechanism rather than prose fluency |
| Joint model ablations | Remove goal coupling, remove process execution, shuffle context, equalize candidate support | Identifies the source of any gain |

An external scorer can be exact only where operations/laws are defined. For human text, a learned similarity/likelihood score is a model with uncertainty; do not disguise it as an exact likelihood. Check it against wrong but plausible alternatives. Candidate generation and candidate scoring must have separate coverage and error measurements.

Start with bounded operation sequences the existing records truly label. Candidate families may include unchanged adoption, local rewrite, structural integration, rejection and later independent replacement. Record which are observable in each source. Preserve unresolved actor identity and process order; historical alternatives can be equivalent at the endpoint.

For local goals, distinguish externally requested goal, maker-stated goal, annotator-inferred purpose and analyst hypothesis. ARIES offers request/edit correspondence; it does not establish author adoption. Do not convert CoAuthor handling into a mental-goal label. Use controlled model-production examples for exact requested/realized goals and human revision-purpose sources for their narrower annotated targets. Report each separately.

**Joint-link test:** compare goal prediction with/without process evidence and process prediction with/without goal coupling, using the same candidate set and evidence budget. Include a severed-link or shuffled-association control. The desired result is reciprocal predictive usefulness; the three panels are not assumed to share one representation by design.

**Branches:** inadequate candidate coverage → spend one bounded development branch on broader proposals or retrieval; adequate candidates but poor scores → improve scorer/readout; good scores only with privileged truth → retain assistance boundary; no room beyond cheap alignment → move to less explicit but still known-answer cases rather than decorate the extraction output.
