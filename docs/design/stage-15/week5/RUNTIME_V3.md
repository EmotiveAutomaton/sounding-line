# Week 5 verification pauses and immutable continuations

DESIGN CHECK: LESSONS 3–5. Both scientific directions require a complete independent replay. A yielded verifier pauses; a false or absent verification fails. No incomplete checkpoint becomes COMPLETE. Known-answer native checks exercise actual verification yield, authenticated copy to a new attempt, complete replay, and explicit false verification. Mutation, added files, changed scientific settings and a live predecessor refuse continuation.

The original child correctly rejected a false verification, but classified a deliberately yielded verification as failure. The v3 supervisor and v2 child preserve that refusal for ordinary false verification and distinguish a producer's explicit yielded status. A pause binds every stable checkpoint output, its operation, and the original plan. It grants no scientific admission.

An explicitly reviewed continuation uses a new root, pins the predecessor's plan and pause, verifies its native process has exited, and copies the complete sealed checkpoint tree under descendant CPU accounting. Original bytes are never overwritten. Module, scientific inputs, family, campaign and scientific configuration must match. Only the wall quantum and maximum newly completed draws may change. Yield requests and mutable progress are not inherited. The copied checkpoint producer validates its own semantic bindings before using any prefix; fresh independent replay remains mandatory. Unsealed legacy attempts are not automatically resumed.

The existing v1/v2 supervisors, child and dispatcher remain frozen. V3 jobs use their separate launcher and retain all previous costs under the unchanged family and campaign ceilings. There is no new gear, spend or data-transfer authority.
