# LA bounded-preparation admission requests, version 2

Prepared November 8, 2026; static implementation only. This successor extends
[the original request scaffold](LA_HUMAN_BANK_ADMISSION.md) to recognize the
exact [bounded source preparer](LA_BOUNDED_PREPARATION.md). Both predecessors
and every prior receipt remain immutable. No source, test, model, native worker
or continuation was executed; no commit or acknowledgment was made.

## DESIGN CHECK

The case is a newly built preparer being mistaken for a qualified human source
pipeline. The check binds its literal module, source closure and actual native
oracle-plus-continuation receipts. A template, partial chain, nested fixture
completion, changed population, missing phase usage or copied owner identity
cannot satisfy that check. No scientific outcome changes these conditions.

The smaller route and all LA1/LA2 definitions remain those already declared.
This file chooses no meeting sample, reader, forecast, allocation or resource
threshold. Measured first-five-percent work and any sample route are separate
admissions. The new source path remains independent of AT2 selection.

## Exact extension

`week5_la_admission_prepare_v2` pins the original admission checker and delivered
bounded-preparation manifest. It executes the original request function with
private replacements for only the preparation and continuation receipt checks.
It does not mutate the original module's globals. Original selected-reader,
paired numerical, source, cost and memory gates remain intact; legacy v4 source
receipts retain their original checks. A new bounded receipt must identify
`week5_la_prepare_v1`, its full frozen closure and primary source semantics.

The separately qualified path requires two kinds of real evidence:

1. A completed counted `week5_la_prepare_v1_fixture` with both native phases,
   sealed original/bounded output equality for all eleven configurations and
   all pending-row, completed-reentry and refusal controls. Its nested source
   fixtures and local copy controls are not native continuation proof.
2. Three distinct counted attempts through `week5_la_prepare_v1`, all using
   the fixture's same constructed source path and the frozen five-block
   quantum: execute pause; resumed execute completion followed by independent
   verify pause; then resumed verify completion. The actual PAUSED/COMPLETE
   receipts, exited native identities, descendant CPU usage, original plan
   pins, resume links and `week5_resume_v2` copy manifests must reconcile.
   Every copied checkpoint byte must remain unchanged. Final source bytes
   must equal the original complete oracle, including the known population.

An available oracle with no completed chain is reported as oracle-only; it
cannot validate a new bounded human-source receipt. Missing or incomplete
requests do not acquire completion flags. Qualification costs remain distinct
attempt charges and do not become a human-source forecast. The checker reads
checkpoint metadata only; it never calls a source producer or a model.

## Requests remain nonlaunchable

Every output still has `nonlaunchable=true`, `ready=false`,
`owner_reviewed=false`, and unknown real cost/peak values. The tool writes
only a fresh private JSON review request outside native attempt roots; it
refuses `PLAN.json`. It cannot copy a checkpoint, launch, claim a lease,
modify a budget, ACK or publish.

For source preparation, the former “bounded implementation missing” gate is
replaced by the actual oracle/chain status and the still-unmeasured source
decode, grouping, meeting-label, checkpoint-authentication and peak-memory
requirements. Source continuation is an explicit request kind and keeps all
old source/configuration/phase/cost guards. Paired-reader continuation remains
the original v4 path. Complete human preparation, AT2 selection, paired-load
qualification, masked/causal costs, complete collection and primary inference
each retain their own gates. LA2 receives no new dependency or changed route.

This checker has only been syntax inspected. Before relying on it, the owner
must review and qualify refusal cases for a template substituted for a receipt,
a nested completion, an unfinished chain, changed copied bytes, missing native
usage, reused native identities, missing source pins and a changed population.
No native or human admission is implied by this document or its templates.
