# Counted qualification of the GO3 five-site collection gate

DESIGN CHECK: LESSONS 2–5. A direct handler result is insufficient: qualification
must exercise the actual supervisor, immutable stopped-output copy, fresh child
and independent-verifier pause before a complete verified receipt. Both full
source support and a missing-category descriptive route use the same contract.

The driver `week5_go3_collection_counted_fixture` accepts only the two frozen
constructed cases and one selected stage per invocation. Preparing inputs
creates explicitly artificial five-site producer envelopes and an immutable
whole-input-tree receipt. These are fixture inputs, never native source
completion claims. Every file, original producer closure, archive/licence/
constructed-salt binding, refusal test and component proof is pinned in the
counted plan. Production source modules and their live plans remain unchanged.

For each case, the execution sequence is three separate native attempts:
the first stops at the declared metadata pilot; the second authenticates and
copies the complete stopped output, finishes execution and stops at the fresh
verifier's independent metadata pilot; the third authenticates and copies that
complete output and finishes all-row verification. The driver never starts the
next attempt automatically. Each boundary is available for owner cost review.

The runtime is v7, with the unchanged source/resume semantics and the separately
qualified SQLite journal accounting repair. Each attempt is bounded to 120 CPU
seconds, 600 wall seconds and 1 GiB projected RAM, at most two numerical threads
and one counted lane. Thirty CPU seconds is an unmeasured planning forecast,
not a receipt. Both cases and all failures/verification remain charged within
the existing GO3 and GO family ceilings; no scientific fit or new budget is
introduced.

Refusal coverage includes changed projection bytes; a swapped source site;
missing or duplicated sites; ambiguous terminals; changed stopped checkpoints;
wrong archive, producer or licence bindings; different campaign salts;
incomplete explicit source replay; and exclusion accounting that fails to
reconcile. All five user folds and sparse-category/user descriptive routes are
checked. A passing targeted component receipt is required before any counted
stage; it is not manufactured by the driver.

Every terminal check validates the expected execute/verify boundary, exact
paused-output manifest, all predecessor bytes, native owner exit, released
lease, complete final output hashes and explicit verified true. The final
fixture receipt sums all three attempts. The operating owner receives all
terminal paths for grouped write-through and ACK; the builder does not ACK.

These files are built only. No constructed preparation, targeted test, counted
stage or human source collection has executed under this design yet. Owner
review and the committed collection design are required before launching.
