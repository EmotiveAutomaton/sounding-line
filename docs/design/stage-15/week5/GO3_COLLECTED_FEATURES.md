# GO3 complete collector-bound feature preparation

DESIGN CHECK: LESSONS sections 2-5, particularly complete upstream population,
pin-path identity, model-scope parity, and immutable checkpoint requirements.
The case is the packet's fourteen edit-difference features plus the six released
IteraTeR annotation-category probabilities for every retained Stack revision.
The check is literal known answers, exact original external-model parameters
and probabilities, complete metadata/order parity, and fresh native replay.
An altered, unfinished, mis-scoped or incompletely replayed collection is refused.
Known text changes must alter their declared diff fields; identical text has
zero difference fields. Comment labels never enter a feature or training input.
There is no Stack classifier, habit accuracy, uncertainty or scientific gate here.

This is an immutable successor to the earlier unbound feature builder. It accepts
only `collection_run` and `iterater_train`, authenticates every output of a final
five-site collector, checks its explicit full-replay result and producer identity,
and reauthenticates every original site source. The source archive, licence, salt,
row count, source ordering and projection hashes remain unchanged. The production
entry point accepts only the reviewed collection module; the separate constructed
fixture permits only the actual counted v2 collection-fixture module and its pinned
constructed declaration. The fixture exception is not a production config option.

All source rows are retained in exact site and within-site order, including rows
outside the primary body-edit/reason subset. This preserves the original habit
companion's all-row definition and timestamp tie order. The final feature bank
keeps the existing metadata plus fourteen diff columns and the external model's
probabilities. It contains neither before/after text nor revision comments. It
does not make source support into scientific admission.

The published IteraTeR train file retains SHA-256
`0b1d1dbe74e2a68495cd0770746899c354cf6787450fc6b14b7ee1f95914eb4c`.
Its features are the frozen original `week5_go3_analysis.features`; its standardized
logistic model uses the original C, iteration limit, seed, labels and full row order.
Training vectors are saved in 512-row blocks. Model arrays are saved without pickle
and restored into the same sklearn classes. A separate fixture compares every array
and every probability to the original unsplit `external_intent`, not a second copy
of the checkpointed implementation. These are annotator revision categories, not
writers' own goal statements or participant survey labels.

The declared unit roster is all 512-row external-training blocks, one exact model
fit and all 512-row Stack feature blocks. Both execution and independent verification
pause once after the first ceiling of five percent of that roster. They also honor
resource requests and the operational `max_wall_seconds` boundary between complete
units. Authentication and repeated validation are charged but are not represented
as completed feature units. The external fit and an individual feature block are
atomic work units; native qualification and the counted cost pilot must measure
their worst duration before a corpus continuation is admitted. Long text is never
clipped and no expensive revision is silently discarded.

Completed units use direct final filenames plus hashes and a sealed state. A dirty
or unsealed output is not a resume source; the runtime must copy an authenticated
PAUSED manifest into a new attempt. Source, model, module and numerical-library
bindings remain constant; only the reviewed wall quantum may change. Original
sources, prior attempts and all failed costs remain retained.

The complete bank is an ordered list of sealed parquet blocks rather than a second
large concatenated copy. Its `FEATURES.json` records every block and complete row
accounting. A separately reviewed statistical consumer must authenticate the final
bank before concatenating those blocks in their saved order. No partial bank is
complete or admissible. Verification independently reconstructs the complete
training set, model and every feature/metadata row, checks all storage hashes and
compares all numerical arrays and parquet rows exactly. Serialization hashes are
authenticated independently and do not substitute for value-level comparison.

The planning envelope is 3 GiB and 900-wall-second cooperative quanta, with the
owner selecting counted attempt limits from native measurements. This entire
preparation, its qualification, pilot, all continuations and fresh replay consume
the existing GO3 250,000 CPU-second card and GO 600,000 family ceilings and their
actual remaining headroom; this note grants no fresh allocation. The smaller route
requires a separately frozen whole-editor sample after the counted forecast,
retaining every row of selected editors and the original support/fallback rules.
This full-source implementation never silently chooses that sample itself.
