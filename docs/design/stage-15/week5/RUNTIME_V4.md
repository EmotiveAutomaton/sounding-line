**DESIGN CHECK, 2026-11-07.** The May and July census supervisors stopped on a Windows sharing denial while reading another live attempt's budget progress. Their original failure records and usage remain. This is an operational failure, not a scientific result. The existing policy, runtimes and scientific modules remain immutable.

`week5_policy_v2` retries an unavailable JSON read six times, with delays of 10, 20, 40, 80 and 160 milliseconds. Permission denial, a path disappearing between discovery and reading, and incomplete JSON all remain failures after that bound. No permission change, zero substitute or cached budget value is permitted. Only actual absence can mark an optional path absent; directory-list failure cannot become an empty campaign. Missing progress for an already claimed attempt retains its full cap; unstarted plans remain uncharged. Multiple terminal records still refuse accounting.

Every fresh active contribution is measured CPU plus two times its age at the end of the complete snapshot and the existing two-second sampling interval. This covers elapsed retry/listing time under the two-thread bound. Stale progress retains at least the full cap and never falls below an already measured value. Future timestamps refuse. All prior per-card, family, campaign, slot, memory and calendar rules remain.

`week5_runtime_v4` imports this successor policy and keeps the existing Windows descendant Job containment and full replay. Persistent accounting unavailability is classified as environmental. Job usage is retained on every stopped phase. If the supervisor cannot read even its own Job receipt, it records at least the full attempt cap and requires explicit accounting reconciliation; unreadability cannot erase cost. The owner must reconcile that conservative charge before any later correction.

Validation uses actual exclusive Windows handles to cause transient and persistent read failures, checks retained terminal charges and repeats the test in a fresh process. Focused checks cover malformed/disappearing accounting, absent roots, future clocks, stale/unknown attempts and ambiguous terminals. A complete native arithmetic handler runs through v4 execute, fresh verification and native exit with counted ownership.

For the stopped census, a separate recovery helper checks all recorded predecessor native identities have exited and copies the SQLite committed snapshot through SQLite's backup API, including committed WAL content. It records the original failure/plan/database pins and validates integrity, month/source/salt settings and checkpoint counts. The source files remain untouched. The copied database is execution state only. New attempts must use `week5_ch_census_replay`, which drops `resume_frame` during verification and reconstructs the complete immutable source from ordinal zero. Predecessor cost plus remaining execution plus full replay are charged; no scientific admission follows a checkpoint receipt.
