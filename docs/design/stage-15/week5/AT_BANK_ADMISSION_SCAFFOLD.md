# Corrected reader-bank qualification and measured admission

This is a separate, unadmitted preparation driver. All delivered scorers,
collectors, designs, manifests and prior attempts remain immutable. The driver
does not launch a process, claim a lease, register a watcher, acknowledge an
event, commit, write a raw `PLAN.json`, select a model or declare the bank ready.
Its only writable destination is a new private artifact under
`.agent-state/drive-20261107/at-admission-work/`.

## DESIGN CHECK

**The case and its check.** Qualification, a bounded cost measurement and a
measured pilot envelope are different states. The driver must refuse any
transition whose prerequisite is absent, incomplete, changed or merely
projected. It checks completed native plans and all sealed outputs, actual
`verified=true`, both successful descendant CPU receipts, stopped native
owner identity and complete handler source pins. Model inputs bind the exact
ten-model roster and metadata-selected pilot. A weight-file size is never a
measured peak, cost, verification or forecast.

Every gate is operational and identical under either scientific direction.
No human score or effect chooses the next source unit, model subset or gate.
The first-five-percent work remains the existing 165-chunk, four-whole-writer
scope for each of all ten readers. Its 27,007 final-context words cover 7.39%
of the frozen full source. The original numerical kernel, practical bars,
2% fresh-forward sample, precision and 0.0001-nat gate do not change.

**The smaller route.** An unfinished bounded stage yields and preserves its
checkpoint. Its explicit continuation uses the same module, source, science
configuration and all predecessor pins; only the existing reviewed runtime
resume adapter copies evidence. Failed attempts are retained and are not
converted into resumable pauses. The original whole-writer sample and family
continuation rules follow measured costs. No measured scientific sample size
or whole-bank forecast is invented by this driver.

The driver refuses another reader-bank proposal while an earlier bank worker
is actually active. Other independent AT statistical work is not mistaken for
this qualification chain. An existing target attempt is never overwritten or
readmitted. Private proposals keep `owner_reviewed=false`, `nonlaunchable=true`
and `bank_ready=false`; the owner must review and freeze any real plan through
the existing counted launcher. The fixture flag in a qualification template
refers to existing native platform/core evidence, explicitly not a claim that
the new target fixture has already passed.

## Resources, costs and evidence that is still missing

The actual read-only policy check is made at proposal time. It retains the
current eight-slot policy, concurrent projected-memory reservations, disk,
campaign clock and family/campaign CPU gates. Largest-reader fresh verification
additionally requires at least 28 GiB current commit headroom and 20 GiB RAM;
generic guarded starts retain 26/20 GiB. The native seven-GiB cooperative
thresholds, six-GiB hard floors and sixty-second grace remain unchanged.
The first conservative pretrained-model qualification keeps a declared peak
envelope of at least 20 GiB; no lower-memory exception is inferred from size.
A later measured lower-memory route needs a separately reviewed successor.

Every qualification/chunk has explicit owner-reviewed finite caps, at most
1,700 wall seconds and 7,200 CPU seconds. These are bounds, not forecasts. An
unmeasured first qualification requires the explicit cap-not-forecast label
and omits `forecast_cpu_seconds`; its actual measured outcome supplies the
next stage. A continued pilot chunk requires complete native CPU and observed
guard peaks for that same reader, including every paused segment. The complete
pilot envelope requires all chunks exactly once and refuses duplicate attempt
charges. A partial prefix can support a bounded next chunk but is never called
the complete pilot or a whole-bank forecast.

All AT terminal receipts, including failed attempts and old float32 work,
remain in the accounting snapshot. Successful pilot throughput and separately
charged failures are explicitly distinguished. The separately retained
1,165.546875 diagnostic process CPU seconds remain charged, with an explicit
owner-declared startup/fixture overhead charge. No zero or weight-based
estimate fills missing accounting. This version conservatively retains those
additional charges; changing a demonstrated duplicate charge requires a
separate reviewed accounting correction.

No whole-bank forecast is emitted. All ten complete envelopes, retained
charges and a measured downstream fitting/replay allowance are still required
for that decision. No source subset or replacement model is chosen here.
