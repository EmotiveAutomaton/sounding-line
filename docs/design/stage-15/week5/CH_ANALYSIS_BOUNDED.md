# CH numerical continuation adapter

This proposed operational successor preserves every estimator, source, sample,
control, seed, bootstrap count, floor, fallback, secondary and texture cell in
[CH_ANALYSIS](CH_ANALYSIS.md). Original modules and receipts remain immutable.
It is built for review; no native proof has yet passed and no human admission
is implied.

## DESIGN CHECK

LESSONS 3–5 apply. Every bound cached callback must survive native pause and a
new attempt unchanged. Changed input, configuration or source bytes refuse in
both scientific directions. Null, positive and negative known-answer worlds
retain the original numerical checks. The successor must reproduce the original
entire serialized output for all five cards, including every CH4 secondary.
Both execute and verify must see an owner request at the top-level output.
A verifier starts callback zero and earns no credit from copied computations.

## Exact numerical boundary

`week5_ch_analysis_bounded` calls the original models' `execute_body` without
editing its mathematics. It supplies the same `begin` and `value` callback
interface through the original progress module's process-local active object.
This changes neither a source file nor another process. Scientific output is
compared byte-for-byte with the original fixture output and fresh replay.

Execution checkpoints bind the full inputs, scientific configuration and
implementation hashes. Only the operational `max_new_draws` callback quantum
can change across attempts. Reuse requires the counted runtime's sealed copied
checkpoint hash. Every saved loop is revisited in original order; missing loops,
changed denominators and nonconsecutive values refuse. RNG and row construction
are rerun in the original order before a saved callback is reused.

Successful execution seals the complete scientific output and its binding.
After a verification pause, a new execute child can recognize that sealed output
without recomputing it. The fresh verify child nevertheless restarts every
callback from zero, ignoring both execution and prior verification caches.
Repeated interruptions therefore repeat verification work; all attempts remain
charged. This deliberately retains the original full-recalculation acceptance.

Owner requests are checked before setup and at each original callback boundary,
in both phases. Exact copied predecessor requests remain historical; any changed
request interrupts. A single callback or model setup is not preempted inside a
numerical solver. Actual in-slot timing must establish a callback boundary within
the native grace interval for its admitted source scale; if not, retain the
interruption and implement a separately reviewed finer exact decomposition.
Fast uncheckpointed final summary arithmetic is unchanged.

## Pilot, limits and outstanding fixture

The first completed 5% of a recorded callback loop emits its measured timing.
Copied pilot records stay immutable. New-work counts exclude restored values;
a loop's forecast is never silently promoted to the whole card, setup, other
loops or verification. The packet ceilings, combined native accounting and
owner cost review remain binding. Ordinary texture remains capped at 3,600 CPU
seconds, with the declared shared node-rescore exception unchanged.

Before admission, run a constructed native fixture that exercises execution
pause and sealed continuation, an owner pause during verification, complete
fresh recomputation, exact agreement with all five original serialized numerical
fixtures, unchanged predecessors, changed-input refusal, and a completed-cache
reentry without an elapsed-time pilot rewrite. Run it through the counted
runtime with complete descendant usage and monitor/native-exit evidence.
No such run is commissioned by this document itself.
