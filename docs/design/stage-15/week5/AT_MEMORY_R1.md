# Reader memory admission under the November 11 ruling

Prospective implementation of PACKET_BACK_HALF R1. This draft is not a committed
admission, a passing fixture receipt or a measured reader forecast. Existing
plans, source capsules, guard thresholds and outputs remain unchanged.

## DESIGN CHECK

LESSONS sections 3–5 apply. Resource decisions are independent of effect direction.
Constructed fixtures must prove before-load refusal, exact boundary arithmetic,
the original seven-GiB request and six-GiB hard floors, native peak recording and
refusal of partial, changed, mismatched or unsealed evidence. The scorer retains
AT-FP64-1 and its original 0.0001-nat agreement rule. No lower precision is used.

The new memory profile binds the exact model manifest and scoring context. The
owner must include all applicable completed native chunk measurements when
freezing it. Each measurement binds a complete independently verified producer,
its sealed plan and sealed owned-process guard receipt. A paused chunk or fixture
forecast cannot establish a completed production peak. Execute and verify
measurements both count, and the highest available private-commit peak wins.

Declared peak is 1.25 times that measured private peak, rounded upward to half a
GiB. Until private peaks exist, use 1.5 times the highest completed working set.
With neither, use 2.5 times the authenticated stored tensor element count in
float64 bytes. Tensor headers are read without loading a model; source hashes
remain mandatory. Counted tensor buffers make this fallback conservative.

Start with declared peak plus seven GiB of commit headroom and eight GiB of
available RAM. For an unobserved reader only, the commit start is the smaller
of that new line and its original 26-GiB line (28 for Pythia-1.4B deduplicated),
but never less than declared peak plus six GiB. The original seven-GiB yield
requests, six-GiB hard floors, sixty-second grace and owned termination remain.

The new wrapper delegates the exact existing generic v5 scoring invocation. It
records Windows PeakPagefileUsage as peak private commit and peak working set
from the actual scoring interpreter, including imports and cold load. It never
uses the lightweight virtual-environment launcher as the measured process.
Every guard receipt includes the profile, its input hash and numerical spec.
Completed collection must authenticate both execute and verification evidence.

R1's two engine readers run first. Their first twenty completed chunks determine
the combined full-bank CPU projection and the packet's whole-session sample
route if needed. A new memory envelope alone does not complete that cost review,
the long-queue adapter or the two-reader collection/primary. Those pieces retain
separate explicit readiness states. No scientific claim is made by this guard.
