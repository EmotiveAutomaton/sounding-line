# Two-day runtime and immutable checkpoint continuation

DESIGN CHECK: LESSONS sections 3–5. Operational controls have identical answers
under scientific nulls and alternatives: changed inputs, parameters, saved bytes,
live predecessors, unknown accounting or exhausted resources refuse admission.
Only a reviewed stopping quantum can change. No scientific gate is relaxed.

The language prefix jobs reached their planned block bounds. The preserved
resume adapter does not recognize their `max_new_blocks` setting as operational,
so it correctly refuses a successor that removes the bound. Resume v5 adds that
key only for `week5_la_back_half` and `week5_la_back_half_source_v2`. Invalid,
nonpositive and fractional block bounds still refuse. Draw count, random seed,
phase, source pins, scientific settings and all predecessor pins remain fixed.
Every saved output is authenticated and copied into a new attempt. Independent
verification starts from the handler's preserved replay contract.

Runtime v11 uses child v6, resume v5 and policy v3. The retained Windows Job
kernel still counts every descendant, bounds numerical pools at two threads,
authenticates native ownership and releases the counted lease after exit.
Resource thresholds, eight shared slots, the campaign ceiling, original clocks,
supervisor charges and independent verification requirements are unchanged.
No prior runtime, plan, receipt or scientific handler is edited.

Policy v3 adds only the packet's family ceilings: RF 40,000, CP 60,000, IS 40,000
and SV 60,000 CPU seconds. Older policy readers reject an unknown family even
when its plan is unclaimed. Therefore launcher v9's `freeze_plan` checks the
transition **before writing** a new-family plan under the common admission mutex,
and admission checks it again. Every claimed legacy attempt needs an unambiguous
terminal receipt, bound native owner and verified exit. A missing owner, active
or unexplained attempt, access denial or conflicting terminal refuses the
transition. Existing-family v11 work may coexist with a healthy older worker.
The owner must cooperatively checkpoint and reconcile that worker before new
families are registered; no automatic termination or lease reclamation occurs.
All future owner admissions use launcher v9. The explicit plan runtime label is
checked at review and again before native execution; source closure pins bind it
to the reviewed code. A legacy launcher must not be used after transition.

Qualification requires scoped semantic/copy refusal tests, the actual language
producer's continuation and fresh replay, exact family ceilings, inherited
accounting failure behavior, and refusal of live/unreconciled legacy attempts
including those without leases. A separate native constructed fixture creates
its own real owner, exits, copies its authenticated checkpoint in another process
and verifies the copy in a third. Test doubles are unit tests, not proof of native
exit. Receipts remain in private operational evidence; no human records are used.

This is infrastructure only. It grants no new research, gear, paid call, source
licence, scientific interpretation or permission to restart intentionally parked
GPU work. Event/four-hour/single-pending watcher delivery is unchanged.
