# Bounded MD3 execution

`week5_md3_bounded.py` preserves the full MD3 primary and companion estimators while adding cooperative yield handling. Its constructed proof pauses after the first 100 of the intended 2,000 primary draws, resumes the same draw sequence, completes all rescue and repeat companions at 2,000 draws, and independently reconstructs every saved draw. The complete output is identical to the previously validated unbounded consumer. A verification resource request returns `status=yielded, verified=false`.

Dynamic null trajectories checkpoint after each complete trajectory; primary and companion bootstraps checkpoint actual draws at bounded intervals and immediately on an announced quantum boundary. Primary and companion NPZs have SHA-256 sidecar receipts and input/source bindings. Grouped likelihood iterations inspect the runtime yield request, and no incomplete likelihood becomes a saved draw. A yield during a fit may recompute that unfinished fit on resume; its prior CPU still counts. Source code and scientific inputs remain fixed throughout resume.

The counted pilot uses the intended `draws=2000` with `max_new_draws=100`. Subsequent execution uses the same output tree and inputs, changing only operational quantum limits. Verification uses `independent-replay/` under that tree and reads the parent's yield request. Its completion requires identical results and every saved numeric checkpoint array. Costs from the null stage, primary fits, all companions, repeated warm-ups and independent verification all count toward the initial MD3 and shared-family ceilings. A smaller participant sample, if required by measured cost, is prospectively declared in a separate attempt and keeps all eligible repeat plays for selected people.
