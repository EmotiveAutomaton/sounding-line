old producer cannot reenter because it tries to replace an immutable historical
cost with new elapsed time. `week5_at_precision_migration` accepts only the old
`week5_at_precision_guard` module, its empty configuration and the identical
retained original-v3 failure input. It requires an authenticated pause, matching
owner-plan hash and exited native creation identity. A completed or failed
predecessor, a still-live owner or unavailable identity evidence cannot migrate.

The successor must preserve every predecessor pin, explicitly pin its plan and
pause, and remain in the same charged family and campaign. The original source
plan, failure marker, rows, model manifest and scoring/guard closure must already
be pinned. Every original output must match the complete pause manifest. The
adapter independently reconstructs the complete block roster, offsets, row

and finished-execution receipt before copying anything. Its binding retains
the exact rows, model revision, numerical specification and context.

yield request files are the same operational exclusions used by the ordinary
resume manifest. No original output is edited or removed. Reentry authenticates
the original predecessor and every inherited immutable byte again. A separate
migration receipt records the mapping; all original guard and cost records stay.

independent fresh-forward check remains mandatory before completion.
