# Exact collection after idempotent scoring

This successor admits only the explicitly reviewed scoring v4 and v5 modules
under the unchanged `AT-FP64-1` specification. V5 changes completed-cost reentry;
its scoring function uses v4's exact code object. Original float32 failures,
their costs and the old collection implementations remain intact. No numerical
threshold, source, model, context, model roster or statistical gate changes.

## DESIGN CHECK

**The case and its check.** A fully verified bank may contain original v4
blocks and v5 blocks whose numeric implementation is identical. The new
collector authenticates completion, the complete plan, its full pin map,
literal reviewed scoring-module hashes and original core hashes. It requires
the rows and model manifest to be pinned, exact source bytes, one manifest and
revision per model, matching context and token cap, the same numerical
specification and exact score binding. Missing, duplicate, unknown, changed or
legacy numerical producers refuse under either scientific direction.

`week5_at_collect_v4` preserves the original complete row assembly and emits
each producer's provenance in a separate immutable sidecar. Its independent
verifier recomputes that sidecar and every original collection check.
`week5_at_analysis_v3` changes only the accepted collector and its validation;
the original full statistical handler, selection rules and reader binding
remain. Selected-reader consumers keep their existing numeric/revision checks.

The native fixture scores all 360 constructed rows for every commissioned
model name using a tiny constructed NeoX, mixed v4/v5 producers, and actual
scoring handlers. It separately scores identical input through both producers
and requires byte equality of their numeric blocks. It then executes complete
collection, original 2,000-draw AT2 analysis and reader selection. Missing pins,
old precision, changed context/revision/binding and incomplete-bank fixtures
must refuse. These constructed model labels are software fixtures, never
measurements of the named pretrained models. Nested receipts are explicitly
fixture-only and never production admissions; the counted outer fixture is
independently replayed in a fresh native process.

**The smaller route.** No partial bank or model omission substitutes for this
integrity check. The fixture uses small constructed weights; production work
still needs its original complete bank, measured costs, declared memory margin
and owner admission. This design does not start large-model work or release a
human selected reader.

The numerical compatibility proof covers this exact frozen v4/v5 pair. Any
later producer version needs a separate review. All prior and current attempt
costs remain charged; compatibility never discounts computation.
