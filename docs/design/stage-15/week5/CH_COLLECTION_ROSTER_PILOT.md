# CH1 collection: explicit initial-roster pilot sequence

**Static preparation, unqualified and unadmitted.** The
[bounded collector](CH_COLLECTION_BOUNDED.md) already enforces an exact
completed-unit quantum in both handlers. On a fresh initial traversal,
`max_new_draws = ceil(expected_positions / 20)` stops after the first whole
row at or above five percent of the frozen roster. No new row-processing or
numerical implementation is necessary for that stop.

The missing integration is operation-specific continuation: a single shared
quantum cannot express an initial execute pilot, full remaining execution plus
an independent verification pilot, then full fresh verification in the normal
three-attempt sequence. The separate `week5_ch_collection_pilot_v1` coordinates
those actual existing boundaries using authenticated native pilot receipts.
It preserves every previously delivered implementation and design.

## DESIGN CHECK

The case is a first-five-percent assertion that either never actually stops,
pauses only execution, or advances from an unrelated/partial copied receipt.
The check is two genuine native pauses at exactly `ceil(N/20)` initial roster
rows, each with zero score rows, zero complete target-band fits and zero
analytical rows; the final attempt independently recomputes the entire
unchanged collection and matches all three original output files.

The smaller route and source scope remain those of the original collection.
No prefix becomes an analytical population, and no sampling choice is made
from its outcomes. An earlier environmental or owner interruption remains an
earlier interruption, not a successful pilot. All failed, repeated and resumed
work remains charged to the same CH family.

## What the fraction means

`N` is the complete immutable position-roster denominator from the qualified
source/sample receipt, bound into the native plan. The adapter does not infer
it from unfinished output. The boundary is integer `(N+19)//20`: for example,
9 of 180 constructed rows or 20,000 of a 400,000-row roster. Rounding is
explicit for other denominators. The adapter cannot decide that a source is
complete merely because a caller supplied a number; source admission must
already establish that denominator.

This is **five percent of the initial roster traversal**, not five percent
of full collection work or CPU time. Full-file authentication and setup precede
the first row and are charged. Score-file authentication, complete target-band
optimizations, entropy emission, gzip publication, replay and runtime overhead
are separate work. A row pilot cannot by itself estimate their cost or satisfy
an assertion that five percent of each numerical phase has run. The pilot
receipt records zero complete-fit units and explicitly denies a CPU/full-work
fraction claim. No full-run forecast or cost admission is automated here.

The owner must approve that exact initial-source-unit pilot interpretation and
retain separate measured bounds for later phases before scientific admission.
If an accepted full-card cost forecast requires a different work denominator,
this source-row mechanism is insufficient; do not relabel it as that mechanism.
The original 7,200-CPU-second trigger and family ceiling remain unchanged.

## Actual pause and continuation contract

1. A fresh execution uses the existing collector with the derived row quantum.
   Its database must contain exactly the boundary roster prefix and no scores,
   fits or analytical rows. The wrapper publishes the private execute-pilot
   receipt only after the collector has actually returned `yielded` and closed
   its committed database. The native supervisor then seals the pause.
2. The next separately reviewed attempt uses the runtime's entire authenticated
   checkpoint copy. A copied execute pilot authorizes continuing the original
   full execution. The verify handler then uses the derived quantum in a new
   independent workspace, beginning at row zero. Only an actual verifier yield
   at the same exact prefix publishes the distinct verification-pilot receipt.
3. After the second native pause and owner review, the next copied attempt
   reuses the completed execution seal and performs the entire independent
   verification from source zero. A copied verifier prefix receives no credit.
   All original population, calibration and exact-byte comparisons still apply.

There is no automatic next-attempt launch. The current native plan, original
producer plan, terminal pause, whole copied-output manifest and each intervening
immutable resume link must authenticate a pilot before it can change the phase.
The producer must be terminal. A cycle, changed old pause, unmatched origin,
altered receipt, reinterpreted fraction or missing proof refuses. A record in
the output directory alone cannot authorize continuation.

If execution is interrupted before its boundary, a later authenticated attempt
uses only the remaining number of initial roster rows. Its receipt separates
restored execution rows from new work. If verification is interrupted early,
the next independent verifier restarts from row zero; earlier verification
work remains charged. These cases preserve the existing environmental-resume
rule without calling partial progress a completed pilot.

## Prepared native qualification and remaining gates

`week5_ch_collection_pilot_qualification_v1` is a nonlaunching preparation and
inspection helper. It first requires the counted, complete original-parity
collector fixture and its independent replay. Only its exact constructed
180-row source can enter the three qualification request templates. Every
template keeps admission, commit, source-closure, resource, cost and attempt
fields unresolved. Preparing a request does not launch a worker.

The acceptance helper requires the actual nine-row execute pause, actual
nine-row independent-verifier pause and final full replay. It checks native
owner/child exits, released lease, retained native Job usage, original-byte
parity and both genuine pilot ancestors. Owner confirmation of watcher delivery
and full accounting is separate; child and Job usage must not be double-counted.
The prepared arithmetic fixture covers exact and rounded boundaries and rejects
invalid denominators; it has not been run.

No native stage has been run for this successor. Remaining qualifications are
the original collector's complete fixture, the actual three-stage native chain,
interruption/altered-ancestry refusal, full source scope and denominator binding,
all indivisible-unit/resource limits listed in the bounded collector design,
and honest phase-aware full-card cost admission. No engine, fit, source scan,
test, commit, ACK or shared-record change occurred during this preparation.
