# GO3 one-attempt feature and analysis admission preparation

DESIGN CHECK: LESSONS sections 2-5. This is admission scaffolding around the
unchanged GO3 source, feature and complete-bank analysis modules. It changes no
population, feature, classifier, fold, reference, practical bar or scientific
decision. Source-only collection, feature preparation, constructed qualification,
and scientific admission remain separate states.

The preparer reads bounded metadata and emits at most one candidate plan. It has
no launcher, loop, automatic continuation, ACK or shared-record writer. Even a
successful preparation does not admit work: the owner reviews the one plan and
invokes the existing launcher separately. Default templates have owner review
false and unresolved proof/cost/commit fields; they deliberately refuse.

The feature route requires the complete five-site source collector, its explicit
independent replay, exact collection/source/salt/projection bindings and both
constructed native feature cases. Each feature case must replay the original
published external model, every feature row and its complete metadata in both
execution and verification. A standalone component test is insufficient. The
original training SHA and all delivered source/fold/feature code and design notes
are pinned. Full byte/source authentication remains in the counted handler;
metadata-only preparation does not scan text or claim to revalidate the corpus.

Analysis additionally requires the complete production feature bank bound to
that exact collector, all sixteen informative/uninformative mathematical worlds,
and the actual counted bank consumer on both constructed source branches. Those
two actual-bank qualifications use the primary; the complete mathematical proof
covers every declared cell. The qualification must preserve 2,000 primary draws,
200 texture draws, 1,000 conditional references, 2,000 paired habit draws and all
18 internal complete-unit pilot boundaries. Original numerical parity and fresh
full model/prediction/reference replay are mandatory, including the descriptive
fallback when a category is absent.

Each production plan names one of the original eight cells. Source and feature
support never substitute for an effect. Five editor-disjoint folds, training-only
standardization/priors, all-row habit scope, whole-post halves and timestamp ties,
three donor roles and fixed galleries remain in their original pinned consumers.
No configurable reduction in draws, missing sites or clipped source is provided.

The original combined GO3 250,000 and GO 600,000 CPU-second ceilings are checked
against a fresh owner-reconciled accounting receipt. Its metadata census includes
every known complete, paused and failed GO attempt, plus the existing 30-second
claimed-attempt overhead. Active GO attempts conservatively reserve their entire
cap. The owner must include additional previously charged qualification or setup
costs; the observed census is a lower bound, never a fresh allocation. Any changed
terminal/cost roster invalidates the receipt. Existing policy separately enforces
campaign resources and remains unchanged.

Every attempt has a measured indivisible-unit envelope and a source/cell-bound
forecast, backed by counted native measurement receipts. The original feature
unit is a 512-row block or the external model fit; the analysis unit is an entire
fold or reference draw. A first-five-percent pilot measures only its declared
units, not an assumed fraction of authentication, upfront fitting or full replay.
Both execution and verification retain their own pilots. For forecasts over
7,200 CPU seconds, a continuation past a real pilot requires the exact stopped
plan's owner-reviewed cost evidence. An earlier resource yield can only continue
toward its first pilot; it cannot be relabelled as one. Each proposed attempt is
bounded to at most 7,200 CPU seconds, 14,400 wall seconds and two numerical threads.

The existing analysis memory gate remains frozen at four times uncompressed
parquet bytes against a 3-GiB frame envelope. It is a planning estimate, not peak
RAM. The per-attempt envelope is 3-4 GiB with actual qualification-based headroom.
An over-budget frame yields before any fit. A larger semantic envelope or a
whole-editor sample requires its own separately reviewed plan; this preparer
does not change memory scope during resume or choose a sample.

Only authentic PAUSED predecessors can be named. The candidate preserves all
original pins and the exact source/configuration; only the existing wall quantum
may change. Runtime v7 still authenticates the complete stopped output manifest
and immutable copy. Preparation pins the expected native boundary but does not
claim that a future worker has reached it. The owner inspects the actual terminal
and all outputs before preparing another attempt or recording a completion.

One static publication concern remains explicit. The delivered GO3 feature and
analysis modules call the original PID-temporary JSON writer. Runtime v7's
transient exception accepts UUID-temporary JSON names and PID PROGRESS only.
These scientific modules and the supervisor are not edited here. Admission
requires deterministic publication-compatibility evidence bound to the exact
writer/module/monitor sources. A mere successful native completion cannot prove
that a disappearing-file race is handled. If a separate publication successor
is needed, it requires its own review, qualification and adapter before this
unchanged-module preparer can admit it. No observed failure is invented.

Construction status: scaffolding, refusal cases, source/cost receipt inspection
and static syntax checks only. No tests, model fits, source scan or native work
were executed by this build. Every absent proof remains an explicit prerequisite;
prepared templates are neither queued nor admitted.
