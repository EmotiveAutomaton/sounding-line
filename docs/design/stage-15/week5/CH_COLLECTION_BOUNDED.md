# CH1 complete collection: bounded storage successor

**Prepared, not run or admitted.** This operational successor implements the
existing [collection contract](CH_ANALYSIS.md) and
[filler contract](CH_FILLER_BOUNDED.md). It does not alter source selection,
engine values, analysis scope, controls, entropy definitions, the 44-cell grid
or any prior pinned implementation. The original collector remains the exact
reference. The existing checkpoint helper supplies authentication, sealed
output binding and recognition of a copied historical owner request.

## DESIGN CHECK

The case is a complete engine roster whose dictionary materialization or long
uninterruptible collection prevents safe admission. The check is exact equality
of all three original published outputs after a disk-backed join, owner pause,
authenticated continuation and independent complete raw-score replay. Missing,
duplicate, extra, changed or unverified positions refuse. Constructed scores
remain explicitly constructed and cannot authorize a scientific collection.

The smaller route is the original measured whole-player sample route, frozen
before outcomes and charged under the CH family ceiling. This implementation
does not select that route, reduce any roster, discard a large record, change
an optimizer or relax support. A memory-bound refusal requires a separately
reviewed resource decision or successor, never truncation.

## Complete population and exact numerical order

The new `week5_ch_collection_bounded_v1` requires the same frozen position file
and batch manifest as the original, plus an explicit complete position count
from the already qualified sample receipt. That denominator is an assertion;
it cannot select a source prefix. Counts outside 1–400,000 refuse. The normal
one-million-node collection and the registered 300,000/3,000,000-node subset
collections retain their respective complete rosters and score banks.

An indexed private SQLite database stores roster rows, authenticated scores,
completed target-month/rating-band fits and analytical rows. Each roster key
is unique, every score is joined to its exact original position and node limit,
and every expected position must be scored exactly once. Each batch still
binds its successful replay, report and post-replay score hashes. At most the
original 1,024-position filler interval is held as a sorted filename list.

The final row order remains lexicographic score-key order, not input order or
batch completion order. The same earliest other month supplies calibration,
with the same 400-point rating bands, mating exclusions, outside-top-five
accounting, twenty-choice floor and separately labelled fixed-100 fallback.
For every optimizer objective evaluation the successor streams that group's
rows in the same key order, makes the same NumPy scalar operations and uses
the same built-in sequential sum, bounds and SciPy optimizer. It does not use
a chunked reduction or approximate temperature. This replaces the original
whole-group supported-array list with an iterator; exact parity must still
pass under the pinned environment before admission.

`COLLECTION.json`, `TEMPERATURES.json` and
`PRIVATE_ANALYTICAL_ROWS.jsonl.gz` retain the original contents and bytes.
Additional checkpoints and progress files are private operational evidence.
The original analytical consumer therefore keeps its existing full-population
and constructed-data refusal unchanged.

## Cooperative execution and independent replay

Completed roster, score and analytical rows are transactional. A save occurs
every 100 completed units and at phase boundaries or an owner yield. The
database uses a full-synchronous rollback journal; it is closed before a handler
returns. A new execution attempt may reuse it only through the runtime's whole
authenticated output copy and matching semantic input/configuration binding.
Original attempts remain untouched. An arbitrary existing checkpoint refuses.

`max_new_draws` is an operational completed-unit quantum, used in **both**
execution and verification. Here its unit is one roster, score, analytical or
export row, or one completed target-band optimization. The configuration and
progress record state this meaning. It is not a bootstrap draw, a percent of
CPU work, or a whole-card five-percent boundary. The actual total input count
supplies each row-phase denominator. No `PILOT.json` claiming five percent is
emitted. A forecast above 7,200 CPU-seconds still requires an owner-reviewed,
actually enforced first-five-percent pilot mechanism before scientific start;
this successor alone does not satisfy that gate.

Owner requests are checked before each row, score-file authentication and
calibration row, and between eight-MiB hash blocks. A calibration interrupt
discards the unfinished optimizer state and restarts the same complete
target/band fit in a later attempt. Completed earlier fits are retained.
Interrupted partial fits are never published as estimates or credited as
independent verification.

A single original gzip member is necessary for exact compressed-byte parity.
Publication therefore streams the fully staged rows in order into a new
private partial file. An interrupt retains that file as evidence; the next
attempt starts compression from row zero, without appending or crediting the
partial member. A completed member can publish at the exact N-row quantum,
without requiring an artificial N+1 unit. Its final hash and two JSON receipts
are sealed only after full completion. Failed and abandoned publication work
continues to count toward the family ceiling and output-byte limit.

Verification always creates a new private workspace and rebuilds the whole
roster, every score, every calibration fit and every analytical row from the
immutable inputs. Neither an execution database nor a copied verifier prefix
earns replay credit. Every original scientific file must match byte-for-byte.
An exact historical copied owner request is retained; any different later
request interrupts both handlers.

## Constructed fixture prepared for owner qualification

The separate `week5_ch_collection_bounded_fixture_v1` builds literal score
records without starting Stockfish. Three constructed months cover supported
and below-floor calibrations, choices outside the five, mating exclusions and
uniform two-choice entropy with the independent closed form log(2). A separate
single-month world exercises the absent donor and fixed-temperature fallback.

The fixture runs the entire unchanged original collector as reference, the
successor, full replay, a real three-row execute quantum, a real three-row
verification quantum, copied continuation, late owner requests, an owner
request during actual optimizer traversal and a gzip-row owner interrupt.
It checks exact N-row gzip completion and unchanged predecessor hashes.
Negative cases cover duplicate roster rows, missing/extra/duplicate scores,
wrong nodes, failed replay, changed scores, a false admitted count, changed
input pin, damaged copied database and a self-consistently resealed false
analytical output. Its own verify handler rebuilds the entire constructed
exercise independently. None of these checks has been executed yet.

Its in-process constructed copy/request helpers test handler semantics only.
They do not prove native child exits, lease release, watcher delivery or the
current runtime's actual whole-checkpoint copy. A separately reviewed counted
execute/pause/continue/replay integration remains mandatory. The fixture itself
is a bounded restart unit: if the outer supervisor requests a yield, preserve
its partial output and restart the complete fixture in a fresh empty output.

## Exact resource and admission gates remaining

- Measure each individual JSON read/decode (score/roster row at most four MiB;
  manifest or batch metadata at most sixteen MiB), SQLite commit, index query,
  distinct-player aggregation, gzip final flush/close and atomic publication
  under the admitted scale. These contain no internal cooperative callback.
- SQLite numeric-row storage uses an eight-MiB page cache and disk-backed
  temporary operations. Python retains only one numeric row, one batch's at
  most 1,024 filenames, the bounded manifest and at most 1,024 month/band
  metadata groups. These bounds are structural, not measured peak RAM.
- Owner checks interrupt the optimizer between calibration rows, but each
  SciPy/NumPy row operation and optimizer transition is an indivisible unit.
  Measure its maximum latency and the cost of restarting a whole target-band
  fit. Fit and gzip restarts may consume repeated work; never omit that charge.
- Qualify exact original-output parity, real runtime checkpoint copying,
  fresh-process replay, native exits, lease release and event compatibility.
  Then measure complete setup, execution, replay, disk growth and retained
  interrupted-output bytes; construction measurements do not forecast 400,000
  positions automatically.
- Bind the complete sample and every authenticated score batch, current
  cumulative CH/campaign accounting and resource margins, committed reviewed
  design, exact source closure and an actually enforced pilot when required.
  All work remains within the original 2,500,000-CPU-second CH ceiling.

No launcher, source scan, engine run, model fit, admission, commit, event ACK or
scientific claim is part of this static preparation.
