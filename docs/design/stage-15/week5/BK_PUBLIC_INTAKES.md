## T2.r: historical hold and a proposed recent-window source

The [official revisions API](https://www.mediawiki.org/wiki/API:Revisions) supplies minor-revision flags, not historical bot-account status. A complete current bot-group roster was retrieved without identity queries, but current membership cannot label unflagged historical edits human. The original lifetime-history T2.r remains held on that mapping; no current-roster substitution is admitted.

The [official recent-changes API](https://www.mediawiki.org/wiki/API:RecentChanges) supplies event-level bot flags with approximately thirty-day retention. A bounded actual metadata proof requested no editor names: ten bot-filtered events returned true flags and ten nonbot-filtered events returned false flags. False means **not flagged as a bot event**, not independently verified human authorship. English Wikipedia currently declares CC BY-SA 4.0. Private derivative texts retain source article/revision attribution, licence and derivation notice; public files contain only aggregate metadata, not text or editor identities.

The separate proposed source freezes a seven-day window ending at least thirty minutes before intake and well inside retention. Before content labels, draw one nonredirect namespace-zero article per API random request, without replacement, until 200 have at least fifty revisions by the frozen end. The API random-order limitation is disclosed: each one-item request uses a random starting point; the frozen returned roster, not a claimed reproducible API seed, defines the sample. Keep all rejected candidates and duplicates. No outcome-dependent article replacement is allowed.

For each frozen article, retrieve every revision within the window, every corresponding recent-change flag and the immediate baseline parent. Authenticate both pagination streams, exact revision/parent/time/hash joins, SHA-1 content checksums and chronological continuity. The older baseline has unknown bot status and is explicitly left censored. An inactive article has no observed in-window trajectory; it is not a negative label. Missing or suppressed text/flags remain source-gap records; the one-percent collection rule applies to them, while contradictory bindings fail closed. Cached private API responses permit bounded continuation and complete independent replay of the exact frozen source without querying a changed live history.

The source stops after ten complete articles or four hundred new requests per attempt, retaining partial request caches for a new attempt; requests are serial with a three-hour attempt bound, 32 MiB single-response cap and 4 GiB new-response cap. Retrieval never requests editor identities, comments or identity-filtered queries. Known-answer native controls cover random eligibility, duplicates, both paginations, bot/nonbot flags, repeated content hashes, left-censored baseline, inactive article, hidden/missing flags, wrong checksums and parent gaps. A separate process replays every frozen response and refuses a changed bot projection.

**This recent-window route requires owner scope review.** A later consumer could label only current-at-freeze sentences whose introduction and subsequent lineage are fully observed within the window, excluding bot-affected, reverted, ambiguous and older censored strata. That would be a prospectively named recent-window derivative of T2.r, not the packet's full lifetime question. Token-change alignment, wikitext stripping, twenty-percent rewrite labels and the frozen CoAuthor transfer model are not yet implemented here. No sentence is labelled or scored by this intake.
