# MD source support repair

DESIGN CHECK: LESSONS 2–5 and CONTROLS 6–7. This is source engineering before outcome estimation. Eligibility does not depend on the direction or size of any scientific contrast. The null and either signed alternative receive identical handling. Conflicting first-task records cannot become a scored first play.

The original MD-source attempt and frozen module remain intact. Its unique-counter assumption failed. A no-outcome structural census of the pinned source found 47,067 participants and 91,058 saved plays. All counters are finite positive integers and all task arrays satisfy the published task schema. Four people have seven repeated-counter groups: five groups contain different task arrays and two contain exactly identical arrays. The one repeated first-counter group contains identical task arrays. One saved calendar coordinate is nonfinite. These are support facts, not scientific findings.

The successor `week5_md_source_h1.py` retains a task only when its positive attempt counter uniquely identifies its full numeric task array. Identical task copies collapse to one. Conflicting same-counter groups are excluded and counted; unaffected exact attempt-one tasks remain eligible. No earliest saved task substitutes for a missing attempt one. An identical task whose copies disagree on calendar time retains a missing calendar coordinate. Any counter collision or nonfinite calendar coordinate makes that person's repeat history ineligible. The output exposes this repeat-history mask, and downstream repeat analyses must use it. Primary within-task analyses require no calendar coordinate.

The source ZIP and extracted MATLAB member are pinned before loading. Only task fields are projected; participant identifiers, demographics and clinical fields are omitted. Original files remain private and unchanged. A second MATLAB reader independently rebuilds selection, deduplication, calendar and repeat eligibility, compares every retained numeric value with NaN-aware equality, and reconciles every exclusion count. Hash agreement alone is insufficient. Constructed fixtures exercise identical tasks with conflicting clocks, conflicting first tasks, conflicting later tasks with a valid first task, missing first tasks and missing clocks. A deliberately modified projected task must fail numerical replay even if its receipt hash is updated.

This supersedes only source support handling in MD1–MD3. Estimands, comparators, split rules, gates, seeds and resource limits remain as in [MD1–MD3](MD1-3.md). A successful source replay grants numerical-consumer eligibility, not a scientific conclusion.
