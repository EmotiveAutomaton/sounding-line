# Repaired profiles as trained prediction features

Authorized October 15 with the accepted Gear 3 recommendation. This uses the
complete admitted R3 v7 profiles; it makes no new profile-generation calls.
It asks whether a trained predictor can use those descriptions, rather than
asking the profile-generating language model to act as the final judge.

**DESIGN CHECK.** LESSONS sections 3–5 and CONTROLS sections 1–3 read. With
uninformative profiles, the extra features should not improve held-out prediction.
With a planted profile-to-choice relation, the trained canonical predictor must
use the correct profile and reverse under a donor substitution. Constant-profile,
future-label and option-order controls can fail the apparatus. These fixtures
are software rulers, not a replacement Ghost scientific twin.

## Frozen first comparison

Use canonical ToMpathy `82789fdb50d9` `Backbone` and `Choice`, without modifying
its engine or optimization. Three matched arms: ordinary task features with a
zero profile block; own-history profile features; the already generated matched
donor-history profile features. Hash lowercase word counts into 32 fixed unsigned
SHA-256 buckets and normalize their Euclidean length. Interact these features
with the four action indicators; simply adding a maker-constant vector to every
option would cancel in a choice model. Retain the Stage 14 nine task features.
All arms have the same 164 columns, with zero unused columns in the baseline.
This low-cost lexical representation is a first diagnostic, not the whole semantic
potential of profiles. No vocabulary, dimensionality or penalty is selected on
held-out results. Evidence indices are provenance, not prediction features.

Resolve the 234 existing nonpilot targets against the complete source replay;
require equality of maker, prompt, opening time, menu, text and action, and recover
the actual resolution time. Check every own/donor history record resolved before
the recipient cutoff, which must precede the target. Keep target labels separate
from prepared features. No response content or maker identity is published.

At each target opening time, fit only previously resolved targets and predict
before revealing that target's label. Freeze all three arms and the entire
chronological roster; future outcomes cannot select parameters or alter earlier
predictions. The canonical engine chooses its personal pooling penalty using
only its historical calibration slice. Earliest unsupported cases retain the
engine's explicit uniform cold start. Report cold-start coverage. Existing
personal-frequency and partial-pooling forecasts are secondary descriptive
comparators; they have a different training history and are not matched arms.

Primary: own-profile gain over the matched baseline and matched donor, in
half-Brier loss, margin 0.005. Keep complete predictions, proper log losses,
writer and crossed-prompt descriptive intervals for every frozen contrast.
No e-value, adaptive stopping, additional arm selection or engine promotion is
created. This historical support is exposed, so even an apparent gain needs a
fresh dataset/temporal replication before a family claim.

## Dependencies and operation

Prepared inputs and software controls can run now. The actual human comparison
requires a reviewed research-admission receipt binding this plan, exact engine
implementation/schema hashes, a passed relevant Ghost witness, real-data adapter
validation and the frozen exposed-holdout policy. The receipt must include the
actual file witnesses and their hashes. No missing receipt is interpreted as a
null. The inspected Ghost checkout has no V23 twin output; its next ordinary
six-hour inspection is the continuation point. Do not fabricate a witness from
our constructed unit tests or use another project's mutable code.

`profile_features.py prepare` freezes source/history/profile bindings and exact
feature/label files. `run --admission FILE` refuses before fitting when evidence
is absent or mismatched. Local CPU work only, one thread, 12-hour hard bound and
the standing resource floors; supervision is required before a real launch.
No extra paid reservation is needed. Full internal write-through precedes ACK.

Method precedent: [Sorensen et al. (2025), sections 2–4 and limitations read](https://aclanthology.org/2025.emnlp-main.106.pdf)
evaluates profile-conditioned trained decoders with held-out raters. This first
diagnostic uses a different statistical predictor, chronology and dataset; its
outcome is not a reproduction of that paper or evidence of latent human values.
