# Native profile inputs and exposed-holdout validation

This is the independent preparation commissioned in the October 15 continuation.
It checks source mappings and evaluation roles before the already prepared
three-arm profile comparison can fit human records. It generates no new profiles.

**DESIGN CHECK.** LESSONS 2–5 and CONTROLS 1–3 read. Under the null of a faulty
mapping, an altered action, menu, opening time, resolution time, source identity
or document must fail exact comparison; a target/future history record must fail
chronology. Under correct reconstruction all requested source records agree.
An unavailable record is a failure, never an omitted denominator or an inferred
time. Runtime failure and semantic mismatch have distinct retained outcomes.

Freeze all 234 prepared target identifiers and every own/donor profile-history
identifier for their 31 writers. Bind the existing features, labels, profile
plan, source replay, training/evaluator records, original source roster and each
required raw JSONL. Invoke the exact ToMpathy capsule's native CoAuthor compiler,
using its pinned interpreter, in isolated bounded child calls. Compare every
required decision against its saved Sounding Line source record: source ordinal,
action, offered-text order, document before cursor, opening and terminal resolution
time. Keep explicit exclusions. The canonical compiler and older replay share a
porting ancestor; this is a cross-implementation source-mapping audit, not an
independently collected ground truth or a human-mechanism validation.

The full audit writes a PASS/FAIL native-adapter witness only at completion,
bound to the exact implementation and prepared comparison. It is insufficient
by itself to admit fitting. Preserve all mismatches and never repair live pins.
Maximum wall time is two hours, serial CPU, no model or provider calls, no GPU,
and the standing RAM/commit/disk floors. Partial sessions do not create a witness.

The holdout policy is frozen before fitting: all records are historically exposed;
all 234 targets and three arms run without selection, tuning or optional stopping.
Only records resolved strictly before each target may train its forecast. Own
and donor profile histories must resolve strictly before that recipient's cutoff,
which cannot follow its target opening. No target may appear in its own profile.
Descriptive writer/crossed-prompt intervals are conditional and nonsimultaneous;
they license no confirmatory family decision, fresh-holdout claim or engine
promotion. A future confirmatory result needs separately frozen fresh support
and its applicable error-control witness. Ghost's matching known-world witness
remains a separate dependency; this audit never writes one on its behalf.
