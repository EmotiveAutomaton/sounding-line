## DESIGN CHECK

LESSONS §§3–5: a terminal filename is not a proof; every retained unit must have
its separate native execute/replay, immutable file inventory, original source
ordinals, fixed engine and nodes, actual native exits and retained outer cost.
Under either scientific outcome the accepted intervals must cover every original
ordinal exactly once. Missing, repeated, gapped, overlapping, changed or unsealed
evidence refuses. A failed attempt remains failed even when some sealed units
inside it are reusable. A partial audit is operational evidence only.

## Evidence accepted by the new adapter

`week5_ch_assembly_range_v1` reads the original positions and engine pins plus
an immutable attempt manifest. Each entry explicitly names its original terminal,
PLAN, new post-exit audit, and half-open selected interval. Selection may remove a
duplicated copied prefix only at existing whole-unit boundaries. The full union
must still contain every original ordinal once, so selection cannot drop cases
or select a scientifically favorable subset.

Every attempt gets a new immutable post-exit evidence audit outside its preserved
directory. The audit binds its original disposition, original PLAN and terminal,
outer native-owner files, retained Job accounting and every output file. It never
edits or adds a completion marker to an old attempt. A FAILED attempt without a
historical checkpoint map receives a newly dated current-byte inventory; that
inventory is explicitly new evidence, not a claim that the old supervisor sealed it.

The adapter rechecks actual native exits, owner-to-plan identity, terminal status,
all inventory hashes, source/engine/node/global-denominator equality, queue binding,
all native code pins, each unit seal and its exact original source rows. Every
selected unit already carries an independently computed native replay. The
adapter does not run Stockfish again or infer science from partial score files.

Original COMPLETE and PAUSED inventories must still match their original terminal
receipt using that runtime's declared filename filter. For PAUSED this excludes
basenames `YIELD_REQUEST.json` and `PROGRESS.json`, names ending in `.tmp` and
names containing `.tmp.`. The separate post-exit audit still binds every file,
including this telemetry. Missing scientific outputs remain a refusal.
FAILED records retain their failure and cost. Unresolved monitor failures,
conflicting terminals or unreconciled accounting hold. An unclosed active unit
can remain inside a stopped FAILED/PAUSED directory, but only its sealed prefix
may contribute; the entire active tail remains preserved and explicitly excluded.

Range successors additionally retain their frozen partition, shard identity,
begin/end bounds and constructed/production scope. Original attempt costs are
listed once per original terminal. Copied nested native costs are diagnostic;
they are never added again to outer charges. Historical attempts not selected
as evidence still remain in the campaign cost ledger.

## Outputs and integration

Operational mode writes only `PREFIX_AUDIT.json`, always with
`population_complete:false`, even when its observed coverage is complete. It
reports interval provenance and whether unsealed tails were excluded. It emits
no collection manifest and licenses no analysis.

Full mode requires an exact union from zero through the true source denominator,
then writes `BATCHES.json` in the existing April-calibrated collector's input
shape. Every batch retains its original terminal disposition and evidence-audit
pointer; FAILED/PAUSED provenance is never called `native_complete`. The existing
collector still independently checks score-key coverage and recalculates its
scientific outputs under its original design. Fresh assembly verification repeats
all evidence checks and reconstructs both output objects exactly.

The adapter reads bounded metadata (at most 256 MiB for an inventory), streams
the original roster, and checks owner cancellation during hashing and row traversal.
An interruption yields and later repeats authentication; no partial hash or
partial population receives final admission. Its actual full-scale IO and CPU
cost must be measured in a counted slot before assigning a production cap.

## Production handover boundary

The separately prepared owner procedure signals only the exact original worker
named in its review. It uses the ordinary cooperative pause, authenticates the
whole stopped checkpoint and native identity, and, if an active unit remains,
uses an original-module `max_new_draws:1` continuation to finish that complete
unit and yield cleanly. It preserves all prior directories and charges.

Only after the clean predecessor exits can its sealed end freeze the new partition.
The owner records one active attempt/continuation chain per shard. A separate
durable reservation under the actual shared admission mutex rejects a second
head for the same manifest/shard; continuation requires the exact predecessor's
authenticated PAUSED receipt and native exit. The range adapter does not import
or modify this owner coordination helper. A failed or ambiguous chain holds for
review rather than silently recycling its reservation.

Candidates retain the actual remaining CPU allowance, runtime guards, original
Week 5 freeze/drain, filler limits and source pins. Week 6 needs its own qualified
campaign transition after actual drain. The builder does not signal, stop, launch,
commit or push any production worker while preparing these files.

BK and AT each consume one filler slot. While both are live, at most four chess
ranges fit the six-filler ceiling; a fifth requires another filler to have actually
exited. Every launch still needs a fresh resource and exact native lease snapshot.
Companion leases are counted for shared capacity and are never reclaimed here.
The owner procedure refuses to interrupt the healthy original during the last
hour before the existing freeze and bounds new wall budgets by the actual drain.
