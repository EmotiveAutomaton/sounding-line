## Additive implementation and qualification

`week5_ch_assembly_historical_range_v1.py` retains the original collector's full
output inventory, ordinal, source, unit replay, cost and terminal checks. It adds
the fallback at each native identity inspection and exact identity-file path
context to refusals. Any fallback proof is stored beside its identity-file hash
and original terminal hash in the new post-exit audit. Re-reading an audit checks
those bindings and the complete historical predicate; native identity is also
freshly checked. Unknown identities never become a blanket accepted class.

Constructed controls cover the literal preboot case, live and absent native
identities, current-boot creation/terminal, boot disagreement, non-access-denied
errors, missing timezone and changed proof bindings. A static control excludes
worker pause, restart and termination calls from the recovery helper. The
existing historical helper's controls run beside them. These prepared checks
are not labelled passed until the owner runs the fixed counted harness.

The qualification harness uses two numerical threads, one exclusive counted
lease, 60 CPU seconds and 180 wall seconds, plus the existing supervisor allowance.
Production prefix reauthentication retains 1000 CPU/1800 wall and the same guarded
shared admission, resource floors and exact lease release. Every failure retains
