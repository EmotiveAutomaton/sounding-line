## Checkpoints and resource bounds

A completed work unit is an immutable directory containing a binding, file
hashes/sizes, row counts and timing observation. Publication renames a complete
temporary directory; interrupted temporary directories remain untrusted and
preserved. The state journal records every sealed receipt. On reentry, a missing
journaled unit refuses. An intact unit sealed immediately before a journal-write
interruption can be reconciled by its exact binding and hashes. No arbitrary
partial database is adopted. Source ingestion and response/user buckets are
separately checkpointed. A producer-complete marker alone never satisfies verify.

Every call has a cooperative CPU/wall budget, checks a YIELD_REQUEST, and uses
SQLite progress callbacks. The owner must additionally use the existing native
contained worker with a wall cap no greater than 1,800 seconds; the handler's
default cooperative wall is 1,500 seconds, leaving closure time. An interrupted
unfinished unit is redone from authenticated inputs; completed units survive.
The outer native cap bounds lost work even if one unit cannot complete. Repeated
unit overruns are an engineering/cost hold, never a source sample or exclusion.

Gzip is not randomly resumable here. Reentry during ingestion restarts the
original parser and skips already sealed chunk ordinals after authenticating
the archive and unit bindings. That decompression, hash verification, repeated
work, failed attempts and fresh replay all cost CPU and are counted. This route
does not pretend a cheap random-access checkpoint exists. All sealed hashes are
validated once per handler invocation, then cached within that invocation.

rows rounded up to a complete source chunk. This supplies in-slot parser/output
