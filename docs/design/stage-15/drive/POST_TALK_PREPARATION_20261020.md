## NP1: count recorded probe-like events

**Hypothesis.** Sessions may contain enough substantial corrections, rejection
runs and returns to a prompt to support future probe-oriented reading.
**Method.** Count events in the authenticated frozen session population and
D39 correction ledger, using D38's accepted-span definition. Report descriptive
rates only; no expected information, mechanism identification or new probability.

The complete session population is retained, including sessions with no events.
Count each accepted model span when at least 80% of its original codepoints
have been deleted. The source ledger must identify an earlier acceptance or
edited acceptance in the same session and writer. Blank original spans and
writer-only corrections do not count. D38's subsequent requirement for five
menus on each side supports its gradient calculation and is not an NP1 census
filter. No human text is sent elsewhere.

Count one event for each maximal run of at least three dismissals; acceptance,
edited acceptance or ignoring breaks the run. Count each session after the
first on the same prompt by the same writer, ordered by timestamp then session
identity. The three categories can overlap. Report their separate totals and
rates, their summed rate, the number of sessions with any event and mean
writer-specific rates. Writer/session rows stay in ignored raw storage.

Below one summed event per session follows the packet's rare-event planning
route; exactly one or more follows its common-event route. Neither route
establishes that owner questioning is necessary or sufficient to identify goals.
An empty population is unsupported, distinct from a nonempty zero-event census.

## DR1: metadata-only order component

The separate `week_reading_order` component accepts only session and writer
identities, prompt identity, date and typed-word count. It rejects profile
features and unknown fields. Selection cannot see candidate outcomes.

Freeze a linear-Gaussian coverage heuristic with unit observation noise and
identity prior covariance. Its design vector contains an intercept, prompt
indicators and standardized log-one-plus word count and date. The target is the
mean design vector across that writer's candidate metadata. Select the record
whose rank-one covariance update most reduces target variance. Prompt novelty
enters through the covariance of its prompt indicator. This is expected
variance under the declared model, not measured information gain.

Date order and uniform random order are separate policies. Directed order
breaks exact gain ties by session identity. The exploratory mixture allocates
80% probability to that choice and 20% uniformly among remaining records.
Every step records every remaining candidate's conditional probability and
the selected probability; sampling is without replacement.

Twelve component checks cover the matrix-inverse oracle, probability sums,
full permutations, reproducibility, ordering invariance, monotone variance,
constant metadata, identity failures and outcome-field rejection. This does
not validate the full scientific comparison. Eligibility, source-authenticated
profiles, the fixed gallery, reference-feature thresholds, 200 random orders,
paired inference and full fresh native replay remain to be implemented.

As the existing review requires, deterministic selection has zero off-policy
support. Conditional probabilities are not marginal inclusion probabilities.
The component provides no population weights. Evaluate the eventual policies
on the full retained writer cohort; a weighted population estimator needs its
own validated definition.
