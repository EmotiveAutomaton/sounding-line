# V1 Phase 0: lossless checkpoint storage recovery

DESIGN CHECK: LESSONS 3-5 reread October 16. The storage null is loss, mutation,
selection or premature reuse: all refuse. Under faithful recovery, decompressing
every retained file reproduces its original bytes, and a scratch resumed grid
reproduces every original construction, fit, prediction and complete summary.
No outcome-dependent branch or new scientific acceptance rule is introduced.

The six-hour inspection found the live v2 attempt retaining about 6.2 GiB halfway
through its fixed grid. At the observed per-world size, the full grid would exceed
the frozen 10 GiB attempt cap. The original worker, source, plan and cap stay intact.
Its useful completed checkpoints and any incomplete final world remain preserved.

This separate recovery is built before that cap fires. It is **not launched** by
this document. Before preparation, inspect and fully record the original terminal
and exact native exit. Only a failure explicitly caused by the output-byte ceiling
is eligible; a live process, monitor failure, completed grid or any other failure
requires separate review. The new plan binds the exact reviewed predecessor plan,
all original pins, runtime, complete checkpoint prefix and new source/test/card bytes.

Reuse every complete consecutive world from the beginning, regardless of its
result. A missing constituent, wrong cell, changed hash or completion after a gap
refuses reuse. Regenerate construction traces and rescore saved predictions to
verify each checkpoint; check unique full row support, probability validity and
the full session fit roster. Do not refit completed worlds. An incomplete world
remains in the old attempt and is recomputed in full under the original seed.

Retain all four world files in the new attempt as deterministic gzip level 6,
timestamp zero. Reused files compress their exact original bytes; new files use
the same canonical JSON serializer as v2. Verify round trips and retain hashes
of both original and compressed representations. Keep all original uncompressed
evidence. Compression changes storage only; no fields, precision or rows are cut.

The [v2 construction, fit, statistic and complete grid](V1_PHASE0_V2.md) are
unchanged. Call the original construction, fit and scoring functions. All 150
worlds and every null remain required before the summary or completion receipt.
The full new attempt, including compressed copies of reused worlds, retains the
10 GiB output cap. Each write reserves 16 MiB for metadata. Retained predecessor
evidence stays separately archived, without deletion to satisfy the successor cap.

Deduct the predecessor's entire lifetime from the original 20-hour computation
allowance (conservatively charging any old waits too); retain the 12-hour maximum
resource wait. Keep one numerical thread, exclusive CPU lease, RAM and commit
floors of 8 GiB, disk floor of 20 GiB, native owner/monitor handshake, hard finite
ceiling and immediate terminal supervision. No model or provider calls. Full
calibration results remain internal until the complete required packet; this
resource recovery licenses no downstream study or scientific claim.

Commands after the prerequisite inspection: the project interpreter runs
`-B -m runners.drive.v1_phase0_v3 prepare`, then the reviewed native launcher
registers COMPLETE/FAILED/MONITOR_FAILED and starts the `run` action. A plan or
attempt claim already present refuses preparation/relaunch. No automatic launcher
or new ETA wake is installed by this repair.
