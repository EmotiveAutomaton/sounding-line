# PP3: complete released-change input preparation

This implements the source portion of the commissioned Week 3 PP3 card. It
prepares process features for every one of the 61,504 held ScholaWrite rows,
preserving five projects and twelve project-scoped author identities. The
packet's approximate author count is superseded by the authenticated source
census; no global person identity is inferred. The original annotation labels
and published filtering remain unchanged. No model, primary statistic, empirical
control or scientific admission is produced by this preparation.

## Frozen source and feature rules

Use the existing authenticated all_sorted release and its canonical 15-label to
three-category mapping. Never use the shipped within-project train/test split.
Each unit is a released labelled change row, as consumed by the source protocol;
annotation spans can cover multiple rows and rows are not independent episodes.
Later analysis must leave whole projects out and report project-level uncertainty.

Process features are the log of one plus the preceding interval, a missing-interval
indicator, the log of one plus the current observed burst's row count, insertion
and deletion envelope sizes, four operation indicators, changed-visible-end
indicator, position within the visible before-state and before-state length.
The edit envelope is the exact common-prefix/common-suffix difference, not a
claim about a unique minimal operation sequence. It handles all Unicode codepoints
and does not truncate source text.

Chronology is sorted within project and source author by timestamp and source
ordinal. An interval is unavailable for the first row, timestamp ties or
discontinuous visible states. All rows remain; unavailable intervals use a zero
storage value with a separate missing indicator. Unambiguous long gaps remain
observed, without clipping. Bursts restart at missing intervals or gaps greater
than 2,000 milliseconds. Burst size uses the current and preceding rows only.
These are intervals between publisher-retained edits, not physical keypress pauses.

LaTeX context reads only the visible prefix before the edit: last structural
heading level, open figure/table/equation/align/list/verbatim environments, and
unescaped-dollar parity. This is a frozen lexical structural proxy, not TeX
compilation or whole-manuscript context. No lexical words, label, author ID or
project ID enter the feature vector. Complete private row identities and text
hashes remain available for later content-arm joins; source text is not exported.

## Validation and limits

DESIGN CHECK: LESSONS 1d, 2, 3-5 read for this build. Under both null and
alternative, all source rows, labels and project boundaries must reconstruct;
labels and future content must not change earlier features. Missing timing
must remain flagged. Changed pins, incomplete counts, contradictory labels,
Unicode errors and replay disagreement fail preparation. These are instrument
invariants, not a scientific pass rule. Known answers precede corpus execution.

The entire source is replayed in a separate native process. Preparation uses at
most two numerical threads, one counted CPU slot and at most 180 CPU seconds
for both processes, charged within PP3's original 7,200-second allowance.
The native fixture and targeted tests are also charged. The full classifier,
within-project outcome permutations, frequency comparator, 15-way and content
arms, project uncertainty and full-design cost admission remain separately
required. No reduced reference bank, silent row deletion or raw-data transfer
is authorized by this preparation.
