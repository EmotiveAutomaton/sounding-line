# D30.s: specification texture of the local-marker pause contrast

Registered before this texture run on October 18, 2026, under the October 17
batch plan sections 3.2 and 3.3. Earlier D30 results are exposed. This is
descriptive texture, not confirmation, scientific admission or a new campaign.

**Question.** Does the positive local-minus-pervasive pause association persist
across both adjustment sets explicitly named in D30?

**Method.** Reconstruct the identical eligible occurrences and frozen marker
labels from the verified D30 primary and its one completed extension. Require
parity with both original coefficients and denominators. Specification one
adjusts for length, population frequency, sentence-start position, preceding
punctuation and leave-writer-out surprisal, with writer fixed effects.
Specification two adds raw own-marker count. The median of these two signed
coefficients is the primary. With two specifications the median equals their
mean; both individual results are reported.

These are all the adjustment specifications named by D30. Its marker thresholds
are fixed definitions, not selectable ranges. The crossed random-effects
estimator belongs to D30.p, the second-pipeline card; ScholaWrite belongs to
D30.r after timing admission. Neither is silently folded into this curve.

Use 2,000 paired writer bootstrap resamples, seed 20261017, applying each
resample to both specifications. Report the 95% percentile interval of the
median; retain the shared exhaustive interval-based states, positive direction.
Labels and eligibility stay frozen, so uncertainty conditions on their estimation.
A missing, singular or nonfinite draw is invalid; do not drop or redraw it.

Permute raw log pauses among eligible occurrences within each writer 2,000
times, seed 20261018, and apply the same permutation to both designs. The
upper-tail descriptive probability is (1 + null medians at least the observed
median) / 2001. Report the full null interval and separate this probability
from the percentile-interval state. This raw shuffle destroys nuisance
associations too. It is not a residual permutation, conditional causal test or
evidence that observed pauses were exchangeable. The exact fixed-design OLS
linear functional may replace repeated solves after independent least-squares
parity verification; the target statistic remains identical.

**DESIGN CHECK.** LESSONS sections 3–5 and CONTROLS sections 1–4 reread for this
design. Planted positive and reversed data must preserve direction; exact
zero outcomes must return zero, a null state and permutation probability one.
A planted association must clear its shuffled-outcome reference. Both models
must use identical eligible rows and bootstrap/permutation indices. Changed
inputs, tampered checkpoints, incomplete sources and nonidentifiable designs
refuse. Test serialized yield/resume, immutable reentry and fresh-process
verification before live dispatch. Test the actual counted runtime too.

All 2,000 draws of each kind are retained in hashed consecutive blocks of 100.
A resource or forecast yield occurs only at a saved boundary. One counted CPU
slot, at most two numeric threads, below-normal priority; no GPU or API calls.
Forecast 600 seconds, combined execution/replay cap 1,800 seconds, output cap
256 MiB. The first bootstrap tenth gives the conservative execution pilot.
The unchanged batch runtime enforces source pins, resources and any yield.

**Interpretation and route.** A positive median describes robustness across
these two adjustment sets only. The extension's positive writer-label shuffle
still prevents person-location or automaticity admission. A marginal/null or
reversed median records that texture without replacing the original outcomes.
D30.p remains the next commissioned texture; D30.r still needs source/timing
work. Handling calibration is not applicable to a pause outcome. No new
extension, relaxed control, family stop, paid dispatch or Tier 4 access follows.

Literature context is inherited from the commissioned specification-curve
reference in the batch plan; this implementation makes no new literature or
novelty claim. Public outputs contain aggregates and hashes only.
